# 工具形式与 Token 优化基线

本文约束 `pi-hledit-diff` 的读取、编辑与模型回包。CLI wire 见 `cli/SPEC.md`，完整实现约束见插件 `MAINTENANCE.md`。

## 读取与编辑入口

- `read({path, offset?, limit?})`：保留日常原生参数；模型直调支持的文本时同时返回源码、逐行 `LN#HASH` 和 `proof_id`。无需先读正文再取锚点。
- `read_windows({path, windows})`：同文件 1–8 段不相邻范围，在一次 CLI Snapshot 中取得共享 proof；不接受顶层 offset/limit。
- `hledit_search_anchors`：完整返回的匹配/上下文行可直接用于编辑；只补读未见过的缺口。
- `edit({path, proof_id, changes})`：显式绑定文件及证据代，原子提交同文件非冲突修改。

图片、空文件、不能建立锚点的内容保留原生只读能力，不转码、不发虚构 proof。嵌套 read 保持原生返回结构，不把未进入会话的隐藏结果登记为证据。read_windows、搜索和 edit 为 model-only。

普通 read 默认从第 1 行读最多 2,000 行，单段 CLI JSON 页预算 50 KiB。多个窗口按物理位置合并重叠/相邻段，共享 2,000 行 / 96 KiB JSON 预算；全部段完整才发联合 proof。不完整多窗口应分小批重读所需范围，包括之前完成的段。

## 不可降低的安全保证

1. proof 只来源于完整展示或与实际提交文本逐行核对一致、且可保留的源行；截断源行不能建立 proof。
2. `proof_id` 保留完整随机 ID，不缩成短计数，也不隐式选择当前最新 proof。它与锚点共同定义目标身份。
3. 18 位行校验、原始字节 revision、完整区间覆盖、冲突检测与原子写入保持不变。
4. 旧 proof 只迁移逐行存续且连续的目标；已消费身份不能因相同文本或 token 再出现而复活。
5. 不自动扩大、缩小、拆分、改写或重放调用方表达的编辑。恢复补读只返回证据，不能顺带执行写入。
6. CLI 启动不可用不接管；接管后故障拒绝编辑，不回退为无 proof 普通编辑。其他 read/edit 覆盖后端必须互斥启用。
7. 旧工具名称仅用于识别历史记录，不留可调用别名、不改写会话。当前通用 read/edit 的历史证据须有本插件版本标记。

## 回包组织

- 单段读取尾部仅给实际范围、完成状态、EOF 或续读参数；已完成请求不强制读取剩余文件。
- 多窗口每个物理段只显示一次正文，标题保留原请求编号及实际范围。
- stale 字段诊断只给字段和旧→新锚点；当前源码集中显示一次。映射是核对信息，不是自动修正。
- 成功编辑先验证 editDeltas、产出范围、数量、文本与截断状态。完整一致的 span 仅回 `changes[i].anchors` JSON 数组与行数；已提交的正文不再回灌。
- 完整结构化 span 保留在 details，用于分支恢复与 TUI。后续需要中间新行时精确读取；紧凑首尾 token 不代替未显示的行锚点。
- 后编辑 span 内部预算 400 行 / 96 KiB；不能紧凑显示的 span 共用 80 行 / 16 KiB 正文预算，仅保留实际显示的完整证据。非法 delta/结构仍属 outcome_unknown，不能降级成成功。
- diff 仅用于 TUI，不加入模型正文；单栏、行内高亮及红绿比例色条不变。

## 参数与提示分工

| 位置 | 职责 |
| --- | --- |
| Schema | 类型、必填性、范围、锚点格式 |
| description | 用途及选择时机 |
| promptGuidelines | 跨工具 proof 工作流、完整性与失败边界 |
| 运行时回包 | 当前状态、具体诊断和下一步 |

edit 保持单一有序 `changes` 数组。各项必填 action、anchors、lines；replace 使用一或两个端点，插入严格一个依附锚点。显式 `lines: ""` 表示删除，`"\n"` 表示一行空行。不引入对象联合、旧形状转换或隐式兼容层。

## 锚点编码的选择

当前采用 `LN#` 加三个 Base64url 字符，共 18 位。四字符小写和六位十进制同样可承载 18 位，但字符更短不代表 token 更少。

编码变更必须按同一真实任务的工具定义、读取结果、编辑参数、回包及必要补读总 token 比较；同时检查实际模型对应 tokenizer。局部 tokenizer 结果不等于服务端账单，也不能只用锚点裸串下结论。候选在不同 tokenizer 上有退化或缺乏稳定净收益时保留现有编码，不为字符数重写 Rust 协议或引入分配式身份/词表体系。

## 验收边界

- 普通 read 后直接 edit；新 proof 继续编辑；多窗口与搜索不强制重复读取。
- 跨文件 proof、文件变更、未读完整范围和已消费旧目标必须零写入拒绝。
- 图片、空文件、分页和只读回退不丢能力；嵌套读取不建立 proof。
- 分支切换、reload 与历史结果恢复不串证据；当前和历史名称不能混淆普通原生工具结果。
- 复用已有检查及真实文件输入输出；自动化契约通过不等于真实模型已正确生成参数，也不等于交互 TUI 已验收。
- 端到端调用数和耗时收益需真实任务对照；去掉重复获取锚点不自动等于整个任务更快。
